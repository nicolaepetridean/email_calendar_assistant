# AI Email & Calendar Assistant

Autonomous agent that monitors a Gmail inbox, classifies emails with Azure OpenAI (GPT-4o), and takes actions — archiving, declining, flagging, or coordinating calendar meetings with manager approval.

## How it works

Each incoming email is classified into one of six labels and acted on automatically:

| Label | Action |
|---|---|
| `MEETING_REQUEST` | Finds free calendar slots → emails manager for approval → creates event on `APPROVE` |
| `TASK` | Labels and logs; if `URGENT`, stars the email and notifies manager |
| `INFO_ONLY` | Archives; invoices/receipts also get a `Finance` label |
| `SALES_OUTREACH` | Sends a GPT-drafted polite decline (configurable) and archives |
| `MARKETING` | Archives |
| `SPAM` | Moves to spam |

The `URGENT` modifier is added on top of any label when a deadline or escalation is detected.

## Prerequisites

- Google Cloud project with **Gmail API** and **Google Calendar API** enabled
- **OAuth 2.0 Client ID** (Desktop app type) — downloaded as `credentials.json`
- **Azure OpenAI** resource with a `gpt-4o` deployment
- Docker & Docker Compose

## Setup

### 1 — Google credentials

Two files are required under `credentials/`:

| File | Source |
|---|---|
| `credentials.json` | Download from Google Cloud Console → APIs & Services → Credentials |
| `token.json` | Generated by running `auth.py` once (see step 2) — do not commit |

### 2 — Authenticate with Google (once, locally)

```bash
pip install google-auth-oauthlib
CREDENTIALS_PATH=credentials/credentials.json \
TOKEN_PATH=credentials/token.json \
python auth.py
```

Opens a browser for OAuth consent. Saves `token.json` automatically. The agent refreshes it on its own — only re-run `auth.py` if the token is revoked.

### 3 — Configure environment

```bash
cp .env.example .env
```

Required values to set in `.env`:

| Variable | Description |
|---|---|
| `AZURE_OPENAI_API_KEY` | Azure OpenAI API key |
| `AZURE_OPENAI_ENDPOINT` | e.g. `https://your-resource.openai.azure.com` |
| `AZURE_OPENAI_DEPLOYMENT` | Deployment name, e.g. `gpt-4o` |
| `AZURE_OPENAI_API_VERSION` | e.g. `2024-12-01-preview` |
| `MANAGER_EMAIL` | Who receives and approves meeting requests |

### 4 — Run

```bash
docker compose up --build
```

## Approval flow

1. Meeting request arrives → agent finds free slots → emails manager:
```
[1] Monday, Sep 15 at 10:00 AM – 11:00 AM UTC
[2] Tuesday, Sep 16 at 02:00 PM – 03:00 PM UTC

Reply with:  APPROVE 1   or   REJECT
```
2. Manager replies `APPROVE 1` → calendar event created → confirmation sent to requester
3. Manager replies `REJECT` → logged, no action

## Troubleshooting

| Problem | Fix |
|---|---|
| `token.json not found` | Run `python auth.py` |
| `RefreshError` on startup | Token revoked — run `python auth.py` again |
| Stuck `PENDING` approval | `sqlite3 data/agent.db "UPDATE pending_approvals SET status='REJECTED' WHERE id='<id>'"` |
| Slot times look wrong | `WORKING_HOURS_START`/`END` are UTC hours |

| Variable | Default | Description |
|---|---|---|

| `AZURE_OPENAI_ENDPOINT` | — | Required |
| `AZURE_OPENAI_DEPLOYMENT` | `gpt-4o` | |
| `AZURE_OPENAI_API_VERSION` | `2024-12-01-preview` | |
| `MANAGER_EMAIL` | — | Required |
| `MONITORED_EMAIL` | — | Informational |
| `POLL_INTERVAL` | `60` | Seconds between inbox polls |
| `CALENDAR_ID` | `primary` | Google Calendar to use |
| `MEETING_LOOKAHEAD_DAYS` | `5` | Days ahead to search for free slots |

| `WORKING_HOURS_END` | `17` | UTC hour — end of bookable day |

| `SLOT_STEP_MINUTES` | `30` | Free-slot search granularity |
| `AUTO_DECLINE_SALES` | `true` | Set to `false` to skip polite decline on sales emails |

| `LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `LOG_FORMAT` | `text` | `text` or `json` (for log aggregators) |
